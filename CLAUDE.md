# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

The Flutter mobile client for HealthMate — photograph a lab report, OCR extracts
the test values, chart them over time, optionally share with another user. It is
**frontend only**: everything lives behind the deployed NestJS API at
`https://healthmate-web-7ufp.onrender.com/api`, shared with the web app in
`../HealthMate-web`.

Read `README.md` for architecture, commands and API gotchas, and
`docs/privacy-redaction.md` before touching anything under `lib/core/privacy/`
or the capture flow. `../APP_BUILD_PROMPT.md` is the original build spec —
useful for verified API response shapes, though the app is now built.

## Hard rules

- **Never write or modify backend code.** If something looks missing from the
  API, work around it client-side or ask. The API is finished and deployed.
- **Don't touch `android/`, `ios/`, or Gradle/Kotlin/AGP versions.** The
  toolchain is known-good and a prior attempt died from exactly that drift. If a
  build fails on an SDK or AGP constraint, stop and report it rather than
  bumping a version. Two things in there are sanctioned and must not be
  "cleaned up":
  - launcher-icon resources, regenerated by `dart run flutter_launcher_icons`;
  - `android/app/proguard-rules.pro` and the `proguardFiles` line that
    references it — without them R8 aborts every `--release` build on ML Kit's
    optional script recognisers. Debug builds skip R8, so nothing catches this
    except an actual release build.
- **No barrel files.** Import the file you want. A symbol collision through a
  re-exporting barrel broke the previous attempt's import graph.
- **State management is `provider` (`ChangeNotifier`)** — not Riverpod, not Bloc.
  Routing is `go_router`.
- **Use the latest stable version of every pub.dev package** — check pub.dev
  rather than recalling a constraint from memory.
- `isSelf`/`isOwner` and derived fields like `age`/`bmi` are **server-decided**.
  Never recompute them client-side by comparing usernames.
- The web app (`../HealthMate-web/apps/web`) is the reference implementation for
  every screen, and `common/access.service.ts` in the API is the reference for
  the permission model.

## Privacy invariants

These are load-bearing. Breaking one is a data leak, not a bug.

- `CaptureProvider.sanitizedImagePath` is the **only** image path that may reach
  `ReportRepository`. `originalImagePath` holds the untouched photo and must
  never be uploaded. Both `extract()` and `_analyze()` hard-return when the
  sanitized path is null — keep that guard.
- The redaction review screen is **mandatory**. There must be no path from
  picking an image to uploading one that skips it, including the failure path
  where on-device OCR returns nothing.
- Detected categories other than age/sex **cannot be revealed** by the user
  (`PiiCategoryDisplay.canReveal`). Anything that can't be revealed must also
  start out masked — there is a test asserting that invariant.
- Redaction **overwrites pixels** before encoding. Never replace it with a blur,
  a pixelation or an overlay: those are reversible.
- The prepare step re-encodes the image even when nothing is masked, because
  that is what strips EXIF (GPS, device, timestamp). Don't "optimise" it away.

## Commands

```bash
flutter pub get
flutter run                      # requires a connected device/emulator
flutter analyze                  # must be clean before calling any work done
flutter test
flutter build apk --debug        # sanity-build without a device
dart run flutter_launcher_icons  # after changing assets/icon/
```

## Verification

`flutter analyze` clean and `flutter test` green is the floor, not the bar. For
anything touching UI, real verification is running it on a device and checking
light/dark, a narrow width, and a failure path — see `APP_BUILD_PROMPT.md` §9.

When a device isn't available, prefer a widget test that pumps the screen at
400×800 and 320×560: a `RenderFlex` overflow raises an exception and fails the
test, which is the class of bug that otherwise ships unseen
(`test/screens/auth/auth_screens_test.dart` is the pattern).

Redaction rules are pure Dart over plain `OcrPage` fixtures, so a new report
layout can be reproduced as a test in a few lines with no photograph — add one
to `test/core/privacy/pii_detector_test.dart` with any detector change.

## Design

Material 3, light + dark, seeded from the brand green. The chart palette in
`core/theme/chart_palette.dart` is shared with the web app and validated for
colour-vision-deficiency separation — **colour is never the only channel** for
an out-of-range value, or for any status. The signup password meter follows the
same rule (it labels itself in words).

`AppTheme.brandGradient` is the fixed brand surface used by the splash and the
auth hero. It deliberately does not respond to the system theme.
